# 不動産業務オールインワンSaaS・実装仕様案 v1.0

| 仕様書の前提 | 決定内容 |
|---|---|
| 対象業務 | 賃貸仲介、売買仲介、賃貸管理。物件・顧客・案件・契約・書類・請求入金・修繕・オーナー報告を同じシステムで扱う。 |
| 想定顧客 | 賃貸仲介・売買仲介・管理を兼業する不動産会社。店舗や担当者が異なっても、同じ物件・顧客情報を共有できる構成とする。 |
| 外部連携の扱い | 初版は外部業務サービスとの自動連携をすべて対象外とする。 |
| 実装しない処理 | 外部サイトからの自動取得、ポータルへの自動掲載、ブラウザの自動操作による転記、銀行への送金、保証会社への審査申請、外部メール・LINEの自動取得、自動電子署名。該当する操作ボタンも表示しない。 |
| 代わりに実装する処理 | 手入力、CSVの取込み・出力、PDF・画像・書類の登録、社内通知、自社システム内の共有ページ、外部で実施した手続きの結果記録。 |
| AIの位置づけ | 資料読取り・下書き作成は追加可能な独立機能とする。AIサービスを接続しなくても、主要業務をすべて利用できること。未接続時にダミーの解析結果を返さない。 |
| 対象物件 | 住宅の賃貸、住宅・土地の売買、住宅の賃貸管理を標準対象とする。店舗・事務所は追加項目で登録可能にするが、事業用契約専用の計算・帳票は別のテンプレートとして扱う。 |
| 対象外の専門業務 | 分譲マンション管理組合の会計、ホテル運営、投資ファンド会計、自動査定、権利関係や法的適否の自動確定。 |

参考画面（独自設計の参考のみ）: R09 顧客一覧（担当者・対応状態を一覧。色だけでなく「未対応」「対応中」など文字表示）／R03 物件詳細内タブ・写真一括登録・写真ごとの情報編集（ポータル別設定は実装しない）／R08 契約条件を帳票へ反映（基本条件・費用・当事者を分ける）／R04 問い合わせの基本情報と対応履歴を同一画面／R05 修繕対象・依頼先・関連資料を案件単位（見積・承認・施工・請求の状態を分ける）／R06 複数の工事項目を表形式（数量・単位・単価・税・費用負担を独立項目）／R07 入金明細と契約・請求の対応づけ（銀行接続なし、手入力またはCSV）。

## 共通画面仕様
| 項目 | 実装内容 |
|---|---|
| 全体構成 | 左側に業務メニュー、上部に全体検索・店舗切替・通知・利用者メニュー、中央に作業画面。 |
| 左メニュー | ホーム、物件、顧客、仲介案件、予定、契約、書類、請求・入金、オーナー精算、問い合わせ・修繕、更新・退去、集計、設定。利用権限のない項目は表示しない。 |
| 一覧画面 | 上から、画面名・新規登録、検索・絞込み、件数・一括操作、一覧、ページ切替。絞込み条件は利用者別に保存できる。 |
| 一覧の操作 | 並べ替え、列の表示切替、列幅変更、行選択、CSV出力を共通化。行全体を押すと詳細へ移動し、チェックボックスや操作ボタンでは移動しない。 |
| 一覧の表示件数 | 初期50件、25・50・100件から選択。大量データを一度にブラウザへ読み込まない。 |
| 詳細画面 | 上部に名称・番号・現在状態・担当者・主操作を固定し、その下を業務別のタブに分ける。物件・顧客・契約などの関連情報へ相互に移動できる。 |
| 入力画面 | 閲覧と編集を区別。編集中は下部に「保存」「キャンセル」を固定表示し、未保存のまま移動する際は確認する。 |
| 保存状態 | 「未保存」「保存中」「保存済み」「保存失敗」を文字で表示。保存失敗時は入力を保持し、再試行できる。 |
| 入力検証 | 必須不足は項目直下に理由を表示し、画面上部にも件数。金額・日付の不整合は保存前に検証。下書き保存と確定時の検証を分ける。 |
| 同時編集 | 他の利用者が先に更新した場合は上書きを止め、「変更箇所を比較」「最新情報を読み直す」を表示。 |
| デザイン | 背景は薄いグレー、入力・一覧は白、主操作は濃い青。赤はエラー・期限超過、黄は確認待ちに限定し、状態名を併記。 |
| 文字・操作領域 | 本文14〜16px、見出し18〜24px、主要ボタンの高さ40px以上。氏名や物件名を過度に省略しない。 |
| スマートフォン | 一覧はカード表示。写真登録、内見記録、問い合わせ確認、修繕報告をスマートフォンで完了できる。大量の費用入力や帳票編集はPCを主対象。 |
| 空・失敗・権限不足 | データなし、検索結果0件、読み込み失敗、閲覧権限不足を別表示。失敗を「データなし」として扱わない。 |

## 画面
| 画面 | 表示・入力する主な項目 | 操作・保存時のルール |
|---|---|---|
| S01 ホーム | 本日の予定、未対応問い合わせ、期限超過タスク、契約準備中、未入金、承認待ち修繕、更新対象。 | 件数を押すと該当一覧へ移動。「自分」「店舗」「会社」で対象を切替。集計基準日時を表示。 |
| S02 物件一覧 | 物件番号、名称、種別、所在地、賃貸・売買、募集状態、賃料・価格、担当、更新日。 | 名称・住所・番号で検索。種別、店舗、担当、募集状態で絞込み。新規作成、複製、アーカイブ。 |
| S03 物件詳細・登録 | 名称、住所、土地・建物・区画、構造、築年月、階数、面積、交通、権利情報、所有者、担当。 | 「基本情報」「区画」「募集条件」「写真・資料」「契約履歴」「管理・修繕」。物件と募集条件を別保存し、過去の条件を残す。 |
| S04 区画一覧 | 部屋番号、用途、間取り、面積、入居状態、現在契約、募集予定、設備。 | 入居状態と募集状態は別項目。退去予定の部屋を募集可能にする。 |
| S05 写真・資料管理 | ファイル、分類、説明、撮影日、公開範囲、表示順、関連物件・案件。 | 複数登録、並べ替え、一括分類、説明の一括編集。原本を保持し、表示順だけ変えても原本を加工しない。 |
| S06 資料取込み | ファイル、対象物件、資料種別、入力候補、出典ページ、確認状態。 | 初版では手入力・PDF閲覧で利用可能。AI読取りを追加する場合は原本と候補を左右に表示し、確認前に正式台帳へ反映しない。 |
| S07 顧客一覧・詳細 | 個人・法人、氏名・名称、読み、連絡先、住所、役割、担当、希望条件、関連案件、対応履歴。 | 借主・買主・貸主・売主など複数の役割。重複候補を表示するが、自動統合しない。 |
| S08 仲介案件一覧 | 案件番号、賃貸・売買、顧客、対象物件、担当、進行状態、見込金額、次回対応日。 | 表表示と進行状態別の列表示を切替。進行状態の変更時に必要項目を検証。 |
| S09 仲介案件詳細 | 希望条件、提案物件、対応記録、内見、申込み、契約準備、必要書類、費用、タスク。 | 電話・来店・メールなど外部で行った対応を手動記録。外部への送信機能とは区別。 |
| S10 物件提案 | 顧客、候補物件、賃料・価格、面積、費用、入居可能日、担当コメント。 | 登録済み物件から比較表とPDF。自社共有ページでは「気になる」「内見希望」「見送り理由」を受け付ける。 |
| S11 予定・内見 | 件名、種類、日時、担当、顧客、物件、集合場所、鍵の受取方法、実施結果。 | 日・週・月表示。担当者の時間重複は警告し、移動を伴う予定は前後の時間も確認できる。外部カレンダー同期はしない。 |
| S12 申込み管理 | 申込者、同居人、希望入居日、提出書類、保証会社名、貸主確認、審査結果と記録者。 | 書類不足、確認中、承認、否決、取下げを記録。外部審査は実行しない。否決時は理由の閲覧権限を限定できる。 |
| S13 賃貸契約編集 | 当事者、部屋、契約種別、開始・終了日、賃料、共益費、敷金、礼金、更新条件、解約予告、特約。 | 基本条件・月額費用・初期費用・更新解約・書類に分ける。契約条件から費用明細を作成。 |
| S14 売買契約編集 | 売主・買主、複数の土地・建物、売買代金、手付金、残代金、契約日、決済予定日、引渡日、融資条件、特約。 | 一つの契約に複数物件を関連づけ可能。融資期限・書類提出・決済準備はタスクとして管理。 |
| S15 書類一覧・編集 | 書類種別、対象案件・契約、テンプレート、作成版、確認者、状態、作成日。 | 変数を埋めた後に文章・表・写真を編集できる。下書き、社内確認中、承認済み、発行済みを区別。 |
| S16 請求一覧・詳細 | 請求先、対象契約、対象期間、明細、税、請求額、期限、入金済額、残額。 | 定期請求の作成、一時請求、PDF出力、取消・訂正。確定済み請求の金額を直接書き換えない。 |
| S17 入金取込み・照合 | 入金日、名義、金額、参照番号、取込元、対応候補、未配分額。 | CSVまたは手入力。入金を請求へ割り当てる「消込」を担当者が確定。一つの入金を複数請求へ配分可能。 |
| S18 オーナー精算 | 対象月、オーナー、回収済み家賃、管理料、立替費用、繰越、送金予定額、実行記録。 | 計算、確認、確定、送金記録の順。送金自体は外部で実施し、実行日・金額・資料を登録。 |
| S19 問い合わせ一覧・詳細 | 受付日、相手、物件・部屋、分類、緊急度、内容、担当、期限、対応記録。 | 対応を時系列で追記。修繕が必要なら、元の問い合わせと関連づけて修繕案件を作る。 |
| S20 修繕案件 | 対象設備、症状、業者、見積、負担者、承認、施工予定、前後写真、請求、完了確認。 | 修繕登録と見積明細を分離。追加工事は元の見積を上書きせず追加版として保存。 |
| S21 更新管理 | 契約満了日、案内期限、提示条件、回答、書類、更新料、手続き状態。 | 対象を自動抽出し、確認した条件から更新書類・請求を作る。対象になっただけでは契約更新を確定しない。 |
| S22 解約・退去精算 | 申出日、希望日、確認済み解約日、立会い、鍵、最終請求、工事、敷金、追加請求・返金。 | 解約日の変更時に請求・精算への影響を表示。費用負担の判断理由と確認者を記録。 |
| S23 外部利用者ページ | 顧客の提案・提出資料、入居者の申請、オーナーの報告・承認、業者の依頼・写真提出。 | 利用者種別ごとに別の表示。自社システム内の機能とし、第三者の業務サービスへの接続は不要。 |
| S24 集計 | 問い合わせ、内見、申込み、成約、売上見込・確定、入居状況、未入金、修繕件数。 | 集計期間・店舗・担当で絞込み。件数の算定条件と対象データへのリンクを表示。 |

## データ設計
| データ | 保存する内容 |
|---|---|
| 共通識別情報 | 内部ID、会社ID、作成日時、更新日時、作成者、更新者、版番号。内部IDと画面の物件番号・契約番号は別。 |
| 会社・店舗・利用者 | 会社ごとにデータを分離。利用者は所属店舗と権限を持ち、複数店舗への所属を可能とする。 |
| 人・法人 | 氏名・法人名、読み、住所、連絡先。個人と法人を区別し、法人担当者は法人とは別の人物として関連づける。 |
| 関係者の役割 | 人・法人と、物件・案件・契約の関係を保存。同じ人に貸主・売主・購入希望者など複数の役割。 |
| 土地・建物・区画 | 土地、建物、部屋・駐車区画を区別。一つの建物に複数区画、売買契約では複数の土地・建物をまとめて扱う。 |
| 面積 | 数値だけでなく、種類（土地・延床・専有）、基準（登記・実測・壁芯）、単位、根拠資料。異なる基準を上書き統合しない。 |
| 所有・管理関係 | 所有者、持分、適用期間、管理委託先・担当。所有者の変更があっても過去の契約・精算先を変えない。共有所有は精算配分を別途設定。 |
| 募集条件 | 賃貸・売買、賃料・価格、入居可能日、取引態様、掲載用コメント、適用開始日、募集状態。 |
| 仲介案件 | 顧客、担当、物件候補、進行状態、対応履歴、次回対応、成約契約。案件と物件は一対一に限定しない。 |
| 予定・タスク | 実施日時を持つ予定と、完了期限を持つタスクを区別。担当者、対象案件、完了者、完了日時。 |
| 契約と契約版 | 契約の基本識別情報と、条件の版を分ける。版には適用期間、当事者、金額、計算設定、特約、確定者。 |
| 契約当事者 | 契約時点の氏名・法人名・住所などを保存。顧客台帳を後から編集しても締結時の情報を変更しない。 |
| 書類と書類版 | 対象契約、テンプレート版、差込みデータ、編集内容、生成ファイル、承認・発行記録。発行済み版は固定。 |
| 添付ファイル | ファイル名、保存先、容量、種類、関連データ、公開範囲、登録者。ファイル自体と関連づけを分ける。 |
| 請求と請求明細 | 請求先、対象期間、期限、状態と、費目・数量・単価・税・金額の明細。定期請求の元となった契約版を記録。 |
| 入金と入金配分 | 入金そのものと、どの請求にいくら充当したかを別保存。分割入金、合算入金、過入金を扱う。 |
| 敷金などの預り金 | 受入額、充当額、返金額、残高、実際の保管主体。家賃収入とは区別。管理会社が預かっていない敷金も記録できる。 |
| オーナー精算 | 対象期間、対象入金、控除費用、繰越、送金予定、送金記録。同じ入金や費用を複数回精算へ含めない。 |
| 問い合わせ・修繕 | 受付内容、対応記録、見積版、明細、承認、工事写真、請求・支払記録。 |
| 操作記録 | 誰が、いつ、どの情報を、どう変更・出力・確定したか。通常の業務利用者には変更・削除を許可しない。 |

## 業務ルール
- B01 業務日付: 契約日・入居日・対象月などは日本の日付として保存。操作日時は時刻を含めて保存し日本時間で表示。契約開始日・終了日は両日を含む。
- B02 状態の分離: 入居状態、募集状態、案件状態、契約状態を別々に管理。
- B03 契約確定: 下書きは未入力を許容。確定時は当事者、対象物件、契約期間、必須費用、確認済み書類を検証。エラー解消まで確定不可。
- B04 契約期間の重複: 同じ部屋の占有期間が重なる確定契約は通常登録不可。将来の入居契約は現在契約の終了後なら登録可能。例外は管理者承認と理由必須。
- B05 契約条件変更: 変更開始日を持つ新しい契約版を作る。将来分の未確定請求だけを再計算候補とし、確定済み請求や締結済み書類は変更しない。
- B06 月額請求の重複防止: 契約、対象期間、費目、請求種別の組合せを検証し、二重作成しない。再実行時は既存分と新規分を表示。
- B07 日割り計算: 実日数方式、30日固定方式、日割りなしを費目別に設定。30日固定は対象日数の数え方と上限30日の扱いも設定。選択方式を契約版へ保存。
- B08 初期値は実日数方式（対象日数÷当月日数×月額）。開始日・終了日を含む。円未満切捨てを初期値とし、契約条件で変更可能。
- B09 計算例: 月額62,000円、31日の月の16日開始なら16日で32,000円。計算式・日数・月額を確認画面に表示。
- B10 税の設定: 費目ごとに課税・非課税・不課税、税率、税込・税抜。賃貸であることだけを理由に同じ税区分を一律適用しない。
- B11 税・端数の一貫性: 税率別に集計して税を計算し、丸め方を会社設定として固定。数量・単価の小数計算には十進数。
- B12 仲介手数料: 計算方法、料率、定額、税区分、請求先を設定可能。初版では自動適法判定を表示しない。
- B13 入金配分: 配分合計が入金額を超えない、請求残額を超えないことを検証。過入金は未配分残高として保持し、次月充当または返金を担当者が指定。
- B14 分割・合算入金: 100,000円の請求に60,000円入金→残額40,000円。120,000円の入金を60,000円の請求2件へ配分できる。
- B15 照合候補: 名義、金額、契約情報から候補を表示。同額・同名義で候補が複数ある場合は自動確定しない。担当者が確認して確定。
- B16 請求訂正: 未確定請求は編集可能。確定後は取消記録または差額調整明細を作り、元請求との関係を残す。入金配分済みなら配分への影響確認も必須。
- B17 精算対象: 回収済みの金額を基準。請求しただけの未回収額を送金対象へ含めない。
- B18 管理料: 定額または対象費目に対する料率。賃料のみか共益費などを含むかを明示し、精算書で計算根拠を確認できる。
- B19 精算確定: 対象入金、控除、配分、繰越を確認して確定。精算済みデータの再利用を防ぐ。確定後の差額は訂正履歴または次回調整。
- B20 共有所有者への配分: 所有持分とは別に送金配分。配分率の合計は100％。端数の配分先を指定し、合計一致を検証。
- B21 敷金精算: 預り残高、承認済み充当、既返金、追加請求を別々に計算。返金予定と返金実行を区別し、未実行の返金で残高を消さない。
- B22 修繕負担: 見積明細ごとに貸主・借主・自社などの負担額。合計が明細金額と一致しなければ確定不可。写真だけから負担者を断定しない。
- B23 追加工事: 承認後に金額・施工範囲を変更する場合は新しい版を作り再承認対象。変更前後の差額と理由を表示。
- B24 更新・解約期限: 期限の基準日、何日前・何か月前、休日調整の有無を契約条件として保存。会社設定の変更で過去契約の期限を黙って変えない。
- B25 月次締め: 締め済み期間は通常編集不可。管理者による締め解除には理由必須、影響する請求・精算の再確認を求める。

## 書類・取込み
- 標準出力書類: 物件紹介資料、物件比較表、内見案内、必要書類一覧、初期費用明細、請求書、入金に基づく領収書、オーナー収支報告、修繕見積・報告、更新案内、退去精算書。
- 契約関係書類（重要事項説明書、賃貸借契約書、売買契約書、媒介契約書、更新合意書）は確認済みテンプレートを登録して利用。未登録時は「書式未設定」とし、完成した契約書を装った仮書類を出力しない。
- テンプレート: 書類種別、対象取引、版、適用開始日、承認者。差込み項目と必須項目を指定できる。
- 帳票編集: 文章、表、画像、改ページ、見出し、余白を編集可能。画像を背景に貼るだけの編集不能な帳票にしない。
- 出力形式: PDFと編集可能なDOCX。表データはCSV。
- データ差込み: 作成時の値を固定保存。元台帳の変更後は「元情報が更新されています」と表示し、担当者が明示的に再反映。手動修正文を無断上書きしない。
- 未確認項目: 確認前の値、資料にない値、不一致がある値を区別。未入力をゼロや「該当なし」に置き換えない。
- CSV取込み: アップロード、文字コード確認、列対応、検証、取込予定の表示、確定、結果確認の順。UTF-8と一般的な日本語CSV（Shift_JIS）。
- 重複判定: 会社内の番号があれば優先。名称や住所が近いだけでは自動統合しない。新規・更新・取込除外を行ごとに指定。
- 入金CSV: 必須は入金日・金額。名義・参照番号・口座識別は任意。同じ内容の明細が複数あり得るため、内容一致だけで削除せず重複候補として確認。
- CSV再実行: 取込処理ごとの番号と行の結果を保存。同じ取込処理の再試行は二重登録しない。別ファイルからの同一明細候補は確認対象。
- ファイル: PDF、JPEG、PNG、WebP、DOCX、XLSX、CSV。1ファイル30MB、1回50ファイル（変更可）。実行形式やマクロ付きは不可。実際のファイル種類を確認し、危険なファイルは隔離。
- CSV出力: 式として解釈される文字列を安全に処理。出力対象の列・件数・個人情報を利用者に確認させる。

## 状態
- 賃貸仲介案件: 新規、対応中、提案中、内見調整、内見済み、申込、契約準備、成約、失注、保留。成約には関連する契約の確定が必須。
- 売買仲介案件: 相談、査定準備、媒介受託、販売・紹介中、購入申込、条件調整、契約済み、決済準備、引渡完了、失注・終了。売主側・買主側の案件種別。
- 契約: 下書き、社内確認中、承認済み、締結記録済み、契約期間中、終了、取消。署名済み書類などの登録と確認者により締結を記録。
- 請求: 下書き、確定、取消。未入金・一部入金・入金済み・期限超過は入金配分と期限から算出し、自由入力で切り替えない。
- オーナー精算: 計算中、確認待ち、確定、送金一部記録済み、送金記録済み、訂正。送金記録額が予定額と一致するまで完了扱いにしない。
- 修繕: 受付、現地確認、見積待ち、承認待ち、発注記録済み、施工中、完了確認待ち、完了、中止。請求・支払状況は修繕進行とは別。
- 解約・退去: 申出受付、条件確認、解約日確定、立会い予定、退去確認済み、精算準備、精算確認済み、返金・回収待ち、完了。
- 承認の差戻し: 理由必須。修正後に再申請でき、承認・差戻し履歴を残す。状態を戻しても確定済み金銭記録は自動削除しない。

## 権限・外部利用者
- 会社管理者: 全社設定、利用者、権限、全データ閲覧、締め解除、データ出力。重要操作には再認証。
- 店舗責任者: 権限を持つ店舗の案件・契約確認、担当変更、承認、集計。全社設定の変更は不可。
- 営業担当: 担当範囲の物件・顧客・案件・予定・書類を編集。入金確定・精算確定は初期状態では不可。
- 契約事務担当: 契約編集、書類作成、提出状況確認。承認権限は別に付与。
- 管理・経理担当: 請求、入金配分、オーナー精算、更新・退去、管理報告。確定権限と閲覧権限を分離できる。
- 修繕担当: 問い合わせ、見積、写真、業者手配、完了確認。契約者の不要な本人確認資料は閲覧不可。
- 顧客・入居者: 自分に公開された提案、書類、提出依頼、申請だけを閲覧・操作。他人の情報や社内メモは不可。
- オーナー: 自分が関係する物件の公開済み報告、見積承認依頼、問い合わせ。入居者情報は必要な範囲だけ。
- 工事業者: 割り当てられた依頼、施工場所、必要な連絡先、見積・写真提出。オーナー収支や別業者の情報は不可。
- 承認の意味: 自社ページ上の承認は「その利用者が内容を確認し回答した記録」。認証時刻、対象版、回答を保存するが、外部電子署名による契約締結とは表示を分ける。

## 技術・運用
- 金銭処理の一括確定: 入金配分、精算確定などは全成功か全取消。
- 二重送信防止: 処理ごとの識別番号で実行済みか確認。
- 権限確認: サーバー側で毎回、会社・利用者・対象データの権限を確認。添付ファイルにも同じ条件。
- 認証: パスワードを復元できる形で保存しない。管理者には多要素認証を用意。招待コード発行と本人への受渡しで利用開始。
- 共有リンク: 有効期限と失効機能。本人確認資料、契約、精算情報はリンクだけで閲覧可能にせず、利用者認証を必要とする。
- 通知: アプリ内通知。通知対象、発生条件、既読、担当変更を管理し、同じ条件で大量重複させない。
- 定期処理: 月次請求、期限抽出、通知作成を定期実行。失敗・再実行の履歴を保存し、再実行しても二重作成しない。
- 削除: 取引履歴のある物件・顧客・契約は通常削除せずアーカイブ。
- バックアップ: 毎日取得、RPO/RTO 24時間を目標。
- 性能目標: 区画10,000件、顧客50,000件、同時利用20人。一覧・詳細の95％が2秒以内。PDF生成や大量取込みは進行状況を表示する別処理。
- 障害時: 保存失敗、書類生成失敗、取込失敗を利用者が確認できる。管理者には対象処理・発生時刻・再試行可否を表示。ログへ本人確認資料やパスワードを出力しない。

## 受入確認
- T01 物件から契約への引継ぎ: 物件・顧客・募集条件を登録し、同じ内容を再入力せず賃貸契約の下書きを作成できる。募集条件の変更で確定済み契約が変わらない。
- T02 複数の関係者: 同じ人物に貸主と購入希望者の役割を持たせ、それぞれの物件・案件を確認できる。不要な顧客重複が発生しない。
- T03 契約期間: 同じ部屋の重複する確定契約を止められる。現在契約の終了後に始まる次の契約は登録できる。
- T04 日割り: 62,000円・31日月の16日開始で32,000円。月末開始、2月、うるう年、月途中解約も設定どおり。
- T05 請求の再作成: 同じ月の請求作成を2回実行しても請求が増えない。契約変更後は対象となる未確定分だけを再計算できる。
- T06 部分入金と過入金: 一部入金で残額を正しく表示。過入金を未配分残高として保持し、返金・次月充当に分けられる。
- T07 合算入金: 一つの入金を複数請求へ配分できる。合計配分額が入金額を超える処理を拒否。
- T08 CSVの再取込み: 同じ取込処理を再試行しても重複しない。別ファイルの重複候補を確認でき、正当な同日同額の入金を誤って削除しない。
- T09 オーナー精算: 未回収家賃を送金対象に含めない。精算済み入金を再利用できない。送金予定と実行記録の差額が確認できる。
- T10 書類の固定: 発行後に顧客住所や賃料を変更しても、発行済み書類が変わらない。修正版は別版となり、旧版へ戻って確認できる。
- T11 修繕の変更: 承認後の追加工事で変更版が作られ、再承認が必要。見積明細と負担額の合計が一致しない場合は確定できない。
- T12 退去精算: 敷金の受入・充当・返金予定・実行を分けて追跡。貸主保管の敷金を管理会社の現金残高として扱わない。
- T13 会社間の分離: 別会社の物件・顧客・添付ファイルを、URLや内部IDを直接指定しても閲覧できない。
- T14 外部利用者の分離: オーナー・入居者・工事業者が、自分に公開された対象以外を閲覧できない。社内メモや不要な個人情報も表示されない。
- T15 同時操作: 二人が同じ契約を編集した場合に変更競合を検知。二人が同時に同じ入金を配分しても金額を二重利用できない。
- T16 単体での業務完結: 外部サービスへの接続設定を一切行わずに、物件登録→顧客対応→契約作成→締結記録→請求→入金登録→精算→修繕→更新・退去まで実行できる。
- T17 帳票の実用性: 日本語、長い住所、法人名、複数ページの明細を含むPDF・DOCXを生成し、文字切れ・表の欠落・編集不能な文字画像がない。
- T18 復元と履歴: バックアップから検証環境へ復元できる。訂正前の金額、承認、発行書類、入金配分履歴を復元後も追跡できる。
